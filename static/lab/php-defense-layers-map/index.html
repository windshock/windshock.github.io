PHP Defense Layers Map

PHP 코어에서 사용자 코드 재진입·중단(bailout)·자료구조 변경이 내부 메모리 수명과 충돌하는 지점을 체계화한 연구 지도. L1~L5는 PHP 공식 보안 계층이 아니라 실제 구현·실행 특성·취약 상태를 묶어 설명하는 연구상의 분석 축이다.

실제 보호 메커니즘 실행·수명주기 특성 취약한 상태 / 분석 범주 GitHub 코드·실험 기록 기반 · 자체 재실행 아님
L ≠ PHP 기능
‘Layer(L)’는 연구자가 붙인 분류명이다. L1~L5가 PHP에 독립된 방어 모듈로 추가된 것이 아니다. 보호가 존재하는 경로와, 보호가 없거나 상태가 누락되는 경로를 함께 표현한다.
01

실패가 발생하는 위치 — 내부 동작과 사용자 코드의 교차

엔진이 유지하는 상태 불변식은 언제 깨지는가?
결함은 하나의 코드 줄보다 상태 전이에서 생긴다
`유효한 포인터/소유권/캐시 상태`라는 전제가 사용자 코드 실행 이후에도 유지되는지 보는 것이 이 지도의 핵심이다.
보호가 유효한 경로참조 유지 · 사본 분리 · 완료 후 캐시 · 안전한 순회
보호가 깨진 경로마지막 참조 해제 · 구 포인터 재사용 · 미완료 정리 · GC 래치
판독 원칙: 한 함수의 겉모양이 위험해 보여도, 사용자 코드가 실제 도달했는지와 뒤따르는 재사용이 있는지를 확인해야 한다.

    03

    v4: 결함을 관통하는 세 가지 실패 패턴

    ① 소멸자 재진입 · lifetime reentrancy

    원래 함수가 참조하는 저장소를 정리하는 도중 `__destruct()`가 재진입하여 소유·해제 상태가 달라짐.

    정리 중→__destruct→재진입
    GH-24729 · 객체 저장소 UAF
    GH-24481 · unserialize 컨텍스트

    ② 순회 도중 저장소 변경 · traversal mutation

    직렬화가 원소 포인터를 쥔 동안 `__sleep()`이 같은 HashTable에 추가 쓰기를 수행하고, 저장 공간이 재할당됨.

    foreach→__sleep()→realloc
    V2-C7 · ArrayObject/ArrayIterator

    ③ 정리 중단 · bailout × cleanup

    사용자 코드에서 bailout이 발생해 마지막 참조 초기화 또는 정리 단계가 건너뛰어지고 오래된 상태가 남음.

    fcc_dtor→bailout→stale FCC
    GH-24763 · libxml stale FCC
    GH-24731 · header callback

    이 지도로 신규 후보를 거르는 절차

    1자료구조 확인
    HT · object store · FCC · GC buffer 중 무엇을 읽거나 정리하는가?
    2사용자 코드 진입점
    `__destruct` · `__sleep` · 콜백 · 예외·bailout이 도달 가능한가?
    3실제 수명·소유권
    마지막 참조인가? COW가 일어나는가? 원래 메모리가 해제되는가?
    4방어 기구 분류
    L1~L5 중 해당하는 보호·예외·경계가 있는가? 없는 층위는 왜 없는가?
    5후속 소비자 도달
    무효화된 포인터나 잔류 상태를 실제 다시 읽거나 쓰는가?
    6동적 검증과 반증
    빌드·할당기·오라클·정상 대조를 고정하고 랩에서만 실험.

    해석에서 주의할 점

    L1~L5 ≠ 다섯 개의 순차적인 방화벽. 서로 다른 유형의 상태 불변식과 실행 특성을 묶은 이름이다.

    무발화 ≠ 완전한 안전. 트리거·할당기·빌드·후속 소비가 없으면 신호가 나타나지 않을 수 있다.

    같은 오류 계열 ≠ 같은 패치. 수정 위치와 적용 범위는 함수별·브랜치별 검증이 필요하다.

    본 페이지는 원본 연구 기록을 이해하기 위한 시각화이며, 코드 일부는 교육용 의사코드로 단순화했다.
