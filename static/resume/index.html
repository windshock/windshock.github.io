운영 방식

관리체계 경험을 현재 보안 운영으로 연결한 방식

1. 발견보다 조치 완료까지

위험 식별 → 기술 검증 → 영향도 판단 → 조치 우선순위 → 재검증 → 장기 미조치/보완통제까지 하나의 흐름으로 관리합니다.

2. 정책보다 통제의 실효성

“정책에 있다”보다 실제 공격·운영환경에서 통제가 작동하는지를 확인합니다. VDI, 인증, 결제, EDR 등에서 이 접근을 반복했습니다.

3. 외부 의존성을 신뢰경계로 관리

협력업체 제품·SDK·에이전트의 업데이트, 코드서명, 권한, 암호·인증, 운영채널을 분석하고 개선 이행을 추적합니다.

4. 반복업무는 자동화, 고위험 판단은 사람

AI 에이전트, 보안 스킬, 탐지 규칙, PoC 회귀테스트를 도입해 전문가 시간을 고위험 이슈에 집중시키는 운영방식을 지향합니다.

팀장 역할과의 연결: 관리체계를 문서가 아니라 위험·통제·증적·개선계획·책임소재를 연결하는 운영체계로 다룰 수 있습니다.
2 금융권 IT 통제 · 감사 · 보안진단

현대카드캐피탈의 정보보안 컨설팅·ISO 27001, 신한데이타시스템 인증, 메트라이프 전산감사, CITI EVA를 수행했습니다. 금융회사 내부 보안조직 경력과는 다르지만, 외부 전문가 관점에서 금융 IT 조직의 통제와 증적, 기술 위험을 반복적으로 검토했습니다.

팀장 역할과의 연결: 규제·감사 요구를 현업이 실행할 수 있는 보호대책과 개선과제로 번역하는 경험이 있습니다.
3 협력업체 · 공급망 기술 위험관리

결제 SDK, FIDO·인증 솔루션, VDI, 운영 에이전트, EDR/IPS 등 외부 솔루션의 신뢰경계를 직접 분석해 취약점을 발굴하고 공급업체·KISA·CERT/CC에 책임제보, 패치와 개선 이행을 추적했습니다.

팀장 역할과의 연결: 체크리스트형 협력업체 관리에 그치지 않고, 실제 서비스에 들어오는 제3자 기술의 위험을 검증할 수 있습니다.
4 VDI · 망분리 · 핵심 인프라

AD·SAC·VDI를 SPOF 관점으로 모델링하고 Cloud PC VDI RCE, Citrix VDI 정책 우회 등을 검증했습니다. 망분리 정책 자체뿐 아니라 관리채널, 업데이트 신뢰, 우회 가능성까지 평가했습니다.

팀장 역할과의 연결: 규정 준수 여부와 기술적 실효성 사이의 간극을 직접 확인하고 개선 우선순위를 정할 수 있습니다.
5 Security Assessment as Code · 보안진단 자동화

보안진단 결과를 정적 보고서로 끝내지 않고 PoC·규칙·보안 스킬·회귀테스트로 관리하는 방식을 구축했습니다. 228개 API를 데이터 흐름 기준 5개 검토 단위로 압축하는 등 검토 범위와 반복업무를 자동화했습니다.

팀장 역할과의 연결: 보안조직이 개발·운영의 병목이 되지 않도록 반복 통제는 자동화하고, 사람은 고위험 판단과 예외 의사결정에 집중하도록 설계합니다.

정보보안팀장으로서의 역할 관점

“관리체계와 규제를 운영할 수 있고, 필요하면 그 통제가 실제로 작동하는지 직접 검증할 수 있는 정보보안 리더.”

컨설팅 시절에는 정책·위험평가·인증·감사의 언어를 배웠고, 기업 내부에서는 서비스와 인프라의 실제 보안 통제를 운영하고 검증해 왔습니다. 정보보안팀장으로서는 규제와 인증, 상시 보안성 검토, 협력업체 위험관리, VDI·인프라 통제, 취약점 조치와 탐지·관제 기준 개선이 각각의 업무로 따로 움직이는 것이 아니라 하나의 반복 가능한 관리체계로 움직이도록 만드는 데 기여하겠습니다.
