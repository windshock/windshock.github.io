Assessment method

패치 여부를 확인하는 4단계

CVE 스캐너의 버전 매칭을 넘어, 소스가 복사되고 변형되는 eGovFrame 특성에 맞춘 확인 순서입니다.

→

Feature anchor

패치 커밋이 건드린 Controller, URL, method, JSP, 설정 파일이 현재 시스템에 실제 존재하는지 찾습니다.

→

Vulnerable signature

원본 구버전의 취약 코드 패턴이 남아 있는지 비교합니다. 버전 문자열만으로 판정하지 않습니다.

→

Fixed signature

upstream 보안패치의 인증·인가·경로제한·메서드 제한·소유권 검증이 백포트됐는지 확인합니다.

Runtime regression

URL 보안, CSRF, 역할, 객체 소유권처럼 소스만으로 확정할 수 없는 항목은 실제 권한별 동작으로 재검증합니다.

Evidence levels

현황판에서 사용하는 판정 수준

  • Patch gap candidate — 구형 기능/패턴이 존재하고 후속 보안패치가 확인됨
  • Upstream fix present — 최신 upstream에서 수정 패턴 확인
  • Partial — 일부 보안조치는 있으나 이후 추가 수정 존재
  • Runtime verify — URL security, 역할, 세션, CSRF 등 운영설정 검증 필요
What this is not

“취약 서비스 목록”이 아닙니다

이 페이지는 공개 upstream과 공개 연구 결과를 기반으로 한 방어용 패치 인텔리전스입니다. 특정 운영기관이 실제 취약하다고 단정하지 않으며, 공격 payload나 운영 서비스 대상 PoC를 제공하지 않습니다.

Deployment verification

실제 서비스는 버전이 아니라 배포 코드로 확인해야 합니다.

소스/WAR/SBOM을 upstream 보안 패치 계보와 비교하면 NOT PRESENT · UNPATCHED · BACKPORTED · CUSTOM · RUNTIME-ONLY로 패치 상태를 분리할 수 있습니다. 이 현황판은 그 분석을 위한 공개 베이스라인입니다.
