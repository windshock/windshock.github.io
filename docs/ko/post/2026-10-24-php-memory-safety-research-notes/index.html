PHP 메모리 안전성 연구 노트 (2016–2026): 발견자, 근본 원인, 패치와 검증 수준

2016~2026년 PHP 메모리 안전성 관련 원 연구자 글, 공식 이슈, 코어 개발자 패치 논의와 재현 증거를 정리한 출처 기반 연구 노트. 트래커 상태와 실제 수정·악용 가능성을 구분한다.

이 문서는 「PHP 메모리 안전성의 10년」에 사용된 원문 자료와 검증 수준을 추적하는 연구 노트다. 기여자들의 선행 연구를 정확히 인정하고, 공개된 사례에서 공통 패턴을 추출하되, 제보·재현·수정·악용 가능성을 섞지 않는 것이 목적이다. 자료 확인 기준일은 2026년 10월 24일이다. 일부 트래커·PR 상태는 이후 바뀔 수 있다.

원본 조사는 2016~2026년 문헌과 실제 취약점 발견자의 기술 글, PHP 공식 소스·보안 권고·버그 트래커, PHP Foundation과 Quarkslab 자료, php-internals, FlowFusion 논문을 대조했다. 상세 기록 58건은 windshock/php2shell의 역사적 결함 코퍼스에 연결된다. 58개 기록은 ‘확정된 미수정 취약점 58개’가 아니며, 아래 목록 역시 전체 PHP 취약점의 통계적 표본이 아니다.

다음 구분이 특히 중요하다. GitHub 이슈가 Open이라는 것은 최신 지원 버전에서 취약점이 재현된다는 증거가 아니고, Closed도 패치가 모든 분기에 반영됐다는 증거는 아니다. 원문에 ASan 로그가 첨부됐다고 해서 모든 PHP 설정에서 원격 RCE가 된다는 뜻도 아니다. 경우에 따라 공격자가 서버에서 PHP 코드를 직접 실행할 수 있어야 하거나, 특정 웹서버 설정이나 확장이 필요하다.

Stefan Esser의 Hardened-PHP·Suhosin 연구처럼 2016년 이전의 PHP 하드닝 연구도 이 연대기의 중요한 배경이다. 다만 2016~2026년의 사건인 것처럼 임의의 연도를 붙이지 않는다.

2026년에는 Calif의 8월 11일 신고, OpenAI의 독립 보고와 추가 분석, Wiz의 8월 24일 보고처럼 연구 경위가 다르다. 공로를 한 사람이나 하나의 회사에 독점적으로 귀속시키지 않는다. 이 목록에 이름이 없더라도 기여가 작다는 뜻은 아니며, 어느 연구자·유지보수자가 이 블로그를 공식적으로 승인한다는 의미도 아니다.

Quarkslab 감사, 2026년 수정 경위, 그 사이의 차이#

2025년 PHP Foundation 발표는 Quarkslab의 PHP 코어 감사를 공개했다. OSTIF 발표 등에서 심각도 요약 수치의 표기가 다를 수 있으므로, 단일 severity 분포를 확정해 다시 인용하기보다 원 감사 보고서의 finding별 번호와 최종 판본을 기준으로 재집계하는 것이 맞다.

2026년 10월 PHP Foundation 회고는 OOM 관련 위험 신호를 인지한 뒤 근본 수정까지의 과정에서 호환성, 확장, 가용성, 의사결정의 어려움이 있었다고 밝혔다. 따라서 감사에서 바로 최종 PHP2Shell 익스플로잇이 발견됐다고 서술하거나, 당시 공개되지 않았던 코어 문제를 하나의 미수정 finding으로 단정해서는 안 된다.

어떤 실험으로 계보를 검증할 것인가#

역사적 결함 코퍼스를 연구 도구로 바꾸기 위해서는 기록별로 다음 조건을 채워야 한다.

  • 출처와 수정 계보: original issue/논문, 신고자, 패치 PR·커밋, 어떤 release에 포함됐는지, 영향 버전.
  • 환경: 재현에 필요한 PHP 버전, 확장, SAPI, 빌드·할당기 조건, 실행 중인 워커 동일성.
  • 관측: ASan, MSan, GDB/watchpoint, Valgrind, PHP GC 불변조건처럼 사례별로 적합한 오라클과 그 실행 성공 여부.
  • 증거 수준: 도달, 오류 유발, 탐지, 공격 전제 분석, 수정 차단의 독립 검증. 하나라도 실패하면 그 단계의 증거를 주장하지 않는다.
  • 독립성: 이미 연구자가 알고 입력 생성기에 반영한 사례는 공개 회귀 세트로 분류하고, 도구 동결 후 별도 평가자가 선정한 사례만 제한적인 blind hold-out으로 다룬다.

예를 들어 #78793는 MSan 대조, #76167은 워커 수명 GDB 대조, #10026은 GC 보호 상태 대조, #76846과 #12073은 failure atomicity의 수정 전후 대조군이 된다. 어떤 오라클을 실행하지 않았다는 사실을 음성 결과로 해석해서는 안 된다.

평가 방법론에는 Magma의 reached/triggered/detected 분리, StateAFL의 서버 내부 상태 계측, FuzzBench의 반복 실험·비교 조건 통제가 참고가 된다. 이 자료들은 PHP2Shell 취약점을 별도로 검증해 준 보고서가 아니라, 검증 방법을 설계할 때 참고한 선행 연구다.

공개 상태·한계·관련 자료#

이 노트는 원 연구자와 PHP 코어 개발자의 공개 자료를 정리한 출처 기반 연구 목록이다. 58개 원기록 전체를 모든 버전에서 직접 재현했다는 주장이 아니며, 연구자 개인이 특정 exploitability 평가를 주장한 것과 공식 보안 권고에서 확인한 범위를 동일시하지 않는다. 재현 실험의 일부는 기존 PHP2Shell 분석 랩의 기록에 근거하며, 이 글을 작성하면서 별도의 PHP-FPM/ASan 전수 실행을 하지는 않았다.

대표 글 · php2shell 저장소 · Issue #2 퍼징 · #3 CoreGuard · #4 코퍼스 · #5 판정 신뢰성

미공개로 확인되는 새로운 결함은 상세 공격 절차를 블로그에 쓰기보다 PHP 보안팀에 먼저 책임 신고한다. 연구자·개발자의 기여나 출처에 대한 정정은 언제든 환영한다.
